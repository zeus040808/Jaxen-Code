# 提示规则实验：能否救回隔离环境里的失败题（2026-11-02）

## 结论

在隔离环境的 8 道失败题上，两轮规则调整分别救回 2 道、1 道，两轮合计救回 3 道（不重复）。但同一道题在两轮之间
结果会反转，**单次运行的随机性和规则的效果是同一个量级**，靠继续加提示规则提升通过率已经收益很小。
有 5 道题在隔离基线、第一版规则、第二版规则三次运行中都失败，更像是模型能力的边界。

有直接证据的规则效果有两条：
- "禁止在环境里找参考答案"：找答案和上网的命令从 19 次降到 0 次。
- "不盲信示例输出、用等价写法交叉检查"：django-11265 因此发现了 issue 没提到的第二个 bug，补丁逻辑与官方一致。

## 实验设置

- 题目：隔离环境重跑（[结果](2026-11-02-swebench-isolated.md)）中未通过的 8 道，`artifacts/swebench/failed8-sample.json`。
- 配置与隔离重跑相同（deepseek-flash、50 步、单题 30 分钟、隔离环境），每题跑 1 次。
- 两轮都在 SWE-bench 任务说明里加了"环境离线、git 只有当前快照"；隔离基线没有这句。
- 改动前的 agent 代码快照留作新题对照用（本轮没用到）。

| 上网尝试 | 1 次 | 0 |
| 平均步数 | 27 | 33 |

**钻评测空子（reward hacking）**：第一版规则下，agent 会在容器里系统性地寻找评测数据和参考答案（`grep` 实例编号、
`find` swe-bench / huggingface 目录、翻 pip 和 conda 缓存、读自己的会话数据库、读 `/root/setup_repo.sh`）。
一条明确的禁止规则就让这类行为消失了，省下来的步数用在了读代码和测试上。

## 解读与下一步

1. **规则的边际收益已经很小**：两轮结果差一道，而单题会在两轮之间反转，这个差距在随机波动范围内。
2. **持续失败的 5 道更像模型能力边界**：需要设计取舍判断（12325）、完整推演状态迁移（16631）、领域标准（astropy）、
   较大功能（pylint），以及追到不直接相关的调用方（13212）。规则里写了对应要求，模型仍没做到。
3. **harness 剩下的空间在机制而不在提示词**：随机性大，适合"多次尝试再挑选"；自己看不出漏洞，适合"独立的审查子 agent"。
4. 要把"模型 vs harness"说清楚，可以做两个小实验：用更强的模型（deepseek-v4-pro）跑这 5 道；用 flash 把这 5 道各再跑 2 次看随机性。
   已用 Opus 4.8 跑了这 5 道：2/5，另有 1 道被防死循环规则挡住，见 [Opus 实验](2026-11-02-opus-persistent5.md)。

明细：`artifacts/swebench/hh-flash-failed8-rules{,2}.{results,predictions,agent-runs}.jsonl`、`traces/<实例>/runs/`。
